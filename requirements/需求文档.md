# 酒店 OTA AI 数字员工需求文档

## 1. 项目目标

在阿里服务器端 OpenClaw 直接实现酒店 OTA AI 数字员工。系统通过飞书作为唯一交互入口，以总智能体调度 17 个业务 skill，完成诊断、经营监控、销售基准线、偏差归因、收益建议、审批后执行、推广、口碑和客户订单分析。

本项目不做独立 SaaS 后台，不复刻小满、超级店长、甩手掌柜；它们只作为业务参考。验收标准以本需求文档、OpenClaw skill 可触发能力、飞书交互和安全执行闭环为准。

## 4. 用户角色

- `admin` / 超级管理员：管理飞书角色表、安全配置、所有 skill、审批和紧急停用。
- `owner` / 老板：查看全部诊断和收益建议，审批真实执行动作，修改业务安全边界。
- `operator` / 运营：查看数据、触发诊断、生成建议、发起审批、执行 dry-run、跟踪结果。
- `frontdesk` / 前台：接收任务、上传截图、反馈执行状态，不允许触发调价、推广或评论发布。
- `guest` / 未授权用户：只返回无权限提示，不读取业务数据，不触发业务 skill。

飞书用户必须通过服务器私有角色表映射到上述角色；未在角色表中的用户默认按 `guest` 阻断。

## 5. 核心交互

- 飞书私信：已授权 `admin/owner/operator` 可直接问问题，例如“今天璞悦需要调价吗？”
- 飞书群聊：必须 @机器人 才响应，群聊只允许项目群。
- 定时任务：OpenClaw cron 自动触发经营快照、基准线、偏差诊断、周诊断。
- 审批链路：建议先 dry-run，再由 admin/owner 确认，最后执行并回写日志。

## 7. 渠道 API 与统一数据契约

### 统一来源字段

- `adapter_vendor`: `beyondh | meituan | dindanll | xhotel | manual | database`
- `channel_source`: `meituan | feizhu | douyin | ctrip | wechat | pms | manual`
- `data_source_type`: `meituan_api | beyondh_api | dindanll_api | sqlite_db | mysql_db | postgres_db | rpa | manual_upload | sample_data`
- `source_capability`: `read_only | write_dry_run | write_live_pending | unavailable`
- `field_quality`: `confirmed | inferred | manual_required | unavailable`

`adapter_vendor` 用于区分适配器来源，`channel_source` 只表达业务渠道或数据归属。

### 美团 API 参考

美团 `developer.meituan.com/docs/api` 作为美团渠道 API 参考入口，具体接口、字段和权限待开发者账号确认。美团酒店门票分销平台偏供给/分销预订链路，不直接等同于商家侧 OTA 运营后台 API。

P0/P1 优先接收美团参考字段：HOS 总分、房型可售状态、挂牌价、促销价、已售/可售房量、曝光、浏览、支付转化率、订单量、评分、差评率、评价内容。

### Beyondh PMS 参考

#### 公共协议

请求体包含 `ChannelKey`、`Method`、`BizContent`、`Format`、`Charset`、`Version`、`Timestamp`、`SignType`、`Sign`。HTTP Header 需要 `Content-Type: application/json` 和 `domain`。

签名规则：排除 `Sign` 后按参数名 ASCII 升序拼接 `key=value`，空值也参与签名，末尾追加 ChannelKey 对应 AppKey，再按 `MD5` 或 `SHA256` 加密并转大写。

#### P0/P1 使用的接口

- `Hotel.GetOrgRoomTypes`：查询房型。
- `Ota.GetOtaRoomTypesByOrgId`：查询 OTA 渠道房型。
- `RoomType.GetRealTimeRentRateByRoomTypeId`：查询房型实时售卖情况。
- `Hotel.SearchOrgWithRoomPriceAndRoomCount`：查询房价房量。
- `Hotel.GetChannelQuota`：查询渠道房量配额。
- `Price.SetPriceByRoomTypeId`：审批后修改 Mtop/QZAgent 渠道价格。
- `Price.SetPriceByRateCode`：审批后修改固定价。

#### P2 使用的接口

- `Order.QueryOrders`：订单列表。
- `Order.QuerySingleOrder`：订单详情。
- `Hotel.GetRoomStatus`：查询房态。
- `Room.ModifyRoomStatus`：房态修改，P0/P1 不默认开放真实执行。

### 订单来了 PMS/直连中台参考

订单来了开放平台作为 `dindanll_api` 参考来源，定位是 PMS/直连中台适配器，不是 OTA 渠道。可参考的能力包括：

- PMS 酒店、房型、静态信息查询。
- 房价码、房型价格、房型库存查询。
- 订单查询、可订检查、接单/拒单/取消等直连业务。
- 房价、房态、订单状态变更推送事件。

订单来了涉及 RSA2/SHA1withRSA 签名验签、AES 解密、门店调用凭证和推送回调。P0/P1 只要求 runtime 生成 dry-run 请求和样例归一化输出，不要求真实签名、验签或回调上线。

### 脚本固化原则

签名验签、token、请求构造、字段映射、状态码转换、JSON 校验、身份权限、审批拦截、日志脱敏、dry-run 动作生成必须由脚本固化。skill/模型负责业务解释、缺失信息追问、飞书回复、策略取舍和 admin/owner 审批沟通。

## 8. 安全规则

- 真实调价、房量、房态、推广、公开评论回复必须 admin/owner 确认。
- 未授权飞书用户不得触发业务 skill。
- 默认执行模式为 `dry_run`。
- 渠道 live 开关未打开时禁止真实写接口调用，例如 `BEYONDH_ENABLE_LIVE`、`MEITUAN_ENABLE_LIVE`、`DINDANLL_ENABLE_LIVE` 未明确等于 `1` 时禁止真实写入。
- 不在 skill、日志、飞书消息中输出 `ChannelKey`、`AppKey`、`Sign`、密码、验证码。
- API 失败时进入 fallback：API -> RPA/浏览器自动化 -> 前台人工任务。

## 9. 非目标

- 不开发独立 SaaS 后台。
- 不接微信。
- 不在 P0/P1 实现无审批全自动调价。
- 不把竞品系统功能逐项复刻为验收标准。
- 不在没有客户确认的情况下接入真实账号密码或验证码流程。
- 不把 99 元外部获客诊断产品混入当前正式数字员工主链路；该产品后续单独建机器人或网页报告。
