## 3. P0 Skill 验收

- S1 顶层配置：能返回酒店档案、房型、渠道、权限、缺失配置和审批策略。
- S2 经营房态采集：能返回出租率、ADR、RevPAR、订单、库存、风险项和数据时间。
- S2 可接收美团、订单来了、数据库参考字段或人工上传字段，不依赖 API 已授权。
- S2 可在 MySQL 映射配置完整时通过 `database-query --db-kind mysql --template operating_snapshot` 读取报表库房态快照。
- S3 消息中台：能生成日报、预警、审批、前台任务四类飞书消息。
- S3 消息中台：能按 `admin/owner/operator/frontdesk/guest` 输出不同权限提示和消息路由。
- S14 酒店运营诊断：能输出 OTA 诊断、A/B 任务、负责人和期限。
- S15 销售基准线：能生成当天目标和小时曲线。
- S16 进度偏差诊断：能判断 ahead/normal/behind/abnormal 并给出归因。

## 4. P1 Skill 验收

- S4 环境行情感知：能给出日期行情等级、证据、置信度和对价格/推广/基准线影响。
- S5 智能收益决策：能基于 S2/S4/S9/S15/S16 和统一字段给出调价建议、安全校验和审批要求。
- S5 可在 MySQL 映射配置完整时引用 `price_snapshot` 的房型、门市价、本日房价、房费和间夜证据，但仍只输出建议和 dry-run。
- S6 房价同步执行：能生成 `Price.SetPriceByRoomTypeId` dry-run 请求，展示脱敏请求摘要和审批要求。
- S6 房价同步执行：`operator` 只允许 dry-run；真实执行审批人必须是 `admin` 或 `owner`。
- Runtime 能生成美团/订单来了 dry-run 请求摘要，并能把样例房价、房量、库存、订单字段和数据库只读字段归一化到统一数据契约。
- Runtime 支持 `database-inspect` 探测 MySQL 连接、表、字段和样例；`database-query` 只有在映射配置完整时才启用 MySQL 业务模板。

## 5. 最小演示闭环

飞书按顺序测试：

```text
@机器人 今天璞悦经营情况怎么样？
@机器人 做一次璞悦 OTA 运营诊断。
@机器人 给璞悦生成今日销售基准线。
@机器人 现在进度是否落后？原因是什么？
@机器人 今天璞悦需要调价吗？只给 dry-run 建议。
@机器人 预览执行 KING 房型 Mtop 今天平日价159、周末价189，不要真实执行。
【路人】@机器人 今天璞悦经营情况怎么样？
【前台】@机器人 今天璞悦需要调价吗？
【运营】@机器人 今天璞悦需要调价吗？只给 dry-run 建议。
【老板或admin】@机器人 我确认这次调价审批，请先生成执行预览。
```

预期结果：

- 每一步都能触发对应 skill。
- 所有执行动作都保持 dry-run。
- S6 明确显示需要admin/owner 审批。
- 未授权用户不触发业务 skill；前台越权请求被阻断；运营不能审批 live；`admin/owner` 可以进入审批校验。
- API 未开通时，系统说明使用 `sample_data/manual_upload/rpa` 继续跑诊断和建议。
- 数据库已接入时，系统可使用 `sqlite_db/mysql_db/postgres_db` 作为只读补充来源。
- 回复不暴露任何密钥、签名、验证码、密码。
