# 商用准入清单

本文只记录工程项目上线所需的正式准入标准，不记录会议、协作流程或个人计划。

## 当前状态定义

| 状态 | 含义 | 是否可商用 |
| --- | --- | --- |
| `internal_demo_only` | 安全开关已锁定，但真实只读数据源未接入或未达到商用数据要求 | 否，只能演示和内部试运行 |
| `commercial_blocked` | 安全开关、角色表、日志、数据目录、DB 只读、映射或 DSN 任一关键项不达标 | 否，必须先修复 |
| `commercial_data_ready` | 生产安全开关、角色表、日志目录、只读数据库映射和 DSN 均达标 | 可进入真实数据试运行，不等于允许 live 调价 |

以 `python runtime/hotel_ota_runtime.py env-check` 的 `readiness_stage` 为准。

## P0 准入

| 检查项 | 要求 |
| --- | --- |
| 飞书最终输出 | 最终回复必须调用 `feishu-output-gate` 或等价策略 |
| 配置与密钥 | 不允许在飞书、文档、多维表格中输出 env、角色表、数据库映射、DSN、token、open_id/chat_id |
| 源码与规则文件 | 不允许全文输出 `SKILL.md`、`references/`、`runtime_commands.md`、源码 zip 或完整 runtime JSON |
| 原始经营数据 | 不允许输出订单行级明细、CSV/XLSX/JSON 原始表，只允许聚合摘要 |
| 运维操作 | 飞书业务 Agent 不得声称或执行改文件、git、stash、reset、重启服务、安装模型/插件 |
| 审批链路 | 真实执行必须有 `approval_id`、fresh 数据、dry-run 摘要、admin/owner 审批记录 |
| 数据新鲜度 | demo/sample/stale/manual_chat 不得创建正式审批，不得称为今日实时 |

## P1 准入

| 模块 | 要求 |
| --- | --- |
| S2 经营快报 | 固定输出结论、数据日期、核心指标、风险、建议动作、审批状态 |
| S15 基准线 | 输出目标日期、目标来源、置信度；不得把月累计除以 30 当日目标 |
| S16 进度偏差 | actual 使用订单业务日期或今日已售字段；字段缺失返回 `data_gap`，不得触发正式 S5 |
| S17 订单分析 | 只输出唯一订单数、渠道占比、房型占比、ADR、风险，不输出行级订单 |
| 业务日历 | 必须能自动识别周末、调休、法定节假日、节前节后；调休上班日不得按普通周末涨价 |
| S4 行情感知 | 无业务日历、天气 MCP、活动/竞品聚合或 fresh S2/S16 时只能返回保守行情，不生成强调价结论 |
| S5/S6 调价 | 业务口径确认前只允许 dry-run 和审批预览，不允许 live 写接口 |

## 生产环境变量

```bash
HOTEL_OTA_ENV=production
HOTEL_OTA_FEISHU_DEBUG=0
HOTEL_OTA_FEISHU_FINAL_GATE_REQUIRED=1
HOTEL_OTA_FEISHU_ALLOW_FILE_EXPORT=0
HOTEL_OTA_FEISHU_ALLOW_CONFIG_EXPORT=0
HOTEL_OTA_FEISHU_ALLOW_RAW_DATA_EXPORT=0
HOTEL_OTA_DB_SOURCE_ENABLE=1
HOTEL_OTA_DB_READONLY=1
HOTEL_OTA_DB_KIND=mysql
HOTEL_OTA_DB_PROFILE=report_mysql_prod
HOTEL_OTA_DB_MAPPING_CONFIG=/etc/hotel-ota-ai/database-source.json
HOTEL_OTA_AUTH_CONFIG=/etc/hotel-ota-ai/feishu-role-map.json
```

`HOTEL_OTA_DB_DSN` 必须放在服务器私有 env 文件中，不写入仓库。

## 试运行记录字段

| 字段 | 说明 |
| --- | --- |
| 测试日期 | 复测发生日期 |
| Git 版本 | 当前 commit 或发布包时间戳 |
| 飞书入口 | 群聊、私聊、定时任务或手动 CLI |
| 测试话术 | 原始提问 |
| 触发 skill | S2/S5/S6/S14/S16/S17 等 |
| 数据来源 | MySQL、manual_upload、sample、demo、API、RPA |
| 数据日期 | `data_business_date` 和 `data_snapshot_time` |
| 新鲜度 | `fresh/stale/demo_data` |
| 输出是否过闸 | 通过、拒绝、需补充证据 |
| 审批状态 | 无审批、dry-run、待审批、已批准、已阻断 |
| 人工核对结果 | 正确、偏差、需复核 |
| 问题编号 | 关联问题记录 |

## 正式商用门槛

- P0 安全复测连续 7 天无复现。
- S2/S15/S16 真实数据结果连续 7 天可人工对账。
- S5/S6 连续 10 次 dry-run 调价建议通过人工复核。
- systemd 重启后 `env-check` 仍为 `commercial_data_ready`。
- 发生模型、DB、API、RPA 故障时能返回明确错误，不伪造成经营结论。
- 发布流程具备 GitHub 拉取和 `.tgz` 包兜底两条路径。
