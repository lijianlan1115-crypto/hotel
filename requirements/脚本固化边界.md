# 脚本固化边界

## 1. 结论

本项目采用“代码运行时 + 中文 skill”混合架构。稳定、可验证、容易出错的输入输出逻辑由 `runtime/` 包固化；`runtime/hotel_ota_runtime.py` 保留为兼容 CLI 入口。需要中文业务判断和沟通的部分由 OpenClaw skill 处理。

这样做的目标不是把 skill 写死，而是让模型拿到可靠事实、候选动作和安全拦截结果，再做解释、追问、审批沟通和飞书回复。

## 2. 必须脚本化

- API 签名、验签、token 刷新、请求构造。
- Beyondh、美团、订单来了字段到统一数据契约的映射。
- 原始状态码转换，例如订单来了 `orderStatus` 和美团 `resStatus`。
- JSON 输入校验、必填字段校验、日期和金额格式校验。
- 日志脱敏，禁止输出密钥、签名、验证码、密码。
- 飞书身份解析、角色权限矩阵、未授权用户阻断。
- 数据库只读连接、`database-inspect` 探测、配置化白名单模板、字段映射、DSN 脱敏和自由 SQL 阻断。
- 审批拦截、live 开关检查、dry-run 动作生成。
- 调价动作的底价、封顶价、单次涨跌幅和审批状态检查。

## 3. 半脚本化

- 需求指数 `demand_index`。
- OTA 健康分 `ota_health_score`。
- 销售基准线和小时进度曲线。
- 进度偏差 `ahead | normal | behind | abnormal`。
- 收益建议的候选调价动作和风险等级。

半脚本化的意思是：runtime 先给出可复核的计算结果和候选动作，skill 再结合上下文解释原因、补充风险和生成中文建议。

## 4. 保留给 skill/模型

- 判断用户真实意图和缺失信息。
- 用中文解释诊断结论、证据和建议。
- 生成飞书日报、预警、审批消息和前台任务。
- 在数据不完整时提出合理追问。
- 在多个策略可选时说明取舍。
- 生成评论回复草稿，但公开发布必须审批。

## 5. runtime 模块边界

- `runtime/cli.py`：CLI 命令路由。
- `runtime/common.py`：时间、JSON/base64 输入、输出、脱敏。
- `runtime/contracts.py`：统一数据契约和输出 envelope。
- `runtime/storage.py`：SQLite、日志、审批记录、demo 数据。
- `runtime/adapters/`：Beyondh、美团、订单来了请求构造和样例归一化。
- `runtime/adapters/database.py`：SQLite/MySQL/PostgreSQL 数据库来源适配，V1 只读；MySQL 通过 `/etc/hotel-ota-ai/database-source.json` 多 profile 映射报表库表和字段。
- `runtime/safety/`：身份权限、审批、价格底线、涨降幅、live 开关。
- `runtime/decisions/`：需求指数、OTA 健康、转化诊断、调价、推广、竞对、任务和口碑。

skill 和 OpenClaw 仍只调用 `python runtime/hotel_ota_runtime.py ...`，不直接 import 内部模块。

## 7. 安全边界

- P0/P1 不做真实 API 调用。
- `adapter-request` 只生成 dry-run 请求摘要。
- `normalize-sample` 只使用本地样例字段，不连接外网。
- `database-inspect` 只允许 `connection/tables/columns/sample`；`database-query` 只允许白名单模板，禁止自由 SQL，V1 不做数据库写入。
- 真实写操作必须同时满足：admin/owner 审批、非 dry-run、安全校验通过、对应渠道 live 开关开启。
- 订单来了真实 RSA2 签名、AES 解密和回调验签需等账号、密钥和回调地址确认后再启用。
